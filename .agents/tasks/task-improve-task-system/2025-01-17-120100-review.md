# Task-card link fix, TaskPanel redesign, and ThoughtFlow rename (v2)

Three concerns in one branch: a persistence bug where task-card links went stale after reload, a TaskPanel rewrite introducing dual view modes with filtering, and a cosmetic rename to "ThoughtFlow." All four issues flagged in the v1 review have been addressed—Card View now filters, tab counts respect status filter, the blur/Escape race uses a `cancelledRef` guard, and import validates task data structure before applying it.

**Watch for:** Duplicated default task-group constants between initial state and full-backup import fallback (confirmed). Header still shows unfiltered `tasks.length` while the body shows filtered results (confirmed). `commitEditTitle` can double-fire on Enter if blur also triggers before React unmounts the input (possible).

## High-level view

The persistence fix is clean. `cardTaskLinks` is now the sole authority for card-task relationships, the canvas dot queries it at render time, and import/export round-trips the three task arrays with per-element validation. The only data-hygiene residue is that old localStorage entries may still carry the now-ignored `linkedTaskIds` property on nodes—harmless but never cleaned.

The TaskPanel redesign introduces two filtering dimensions (group tabs + status bar) that both views now respect. The list view handles the "all groups" case with collapsible section headers and correctly applies `statusFilter` within each section. The Card View filters `groupTasks` through `statusFilter` and scopes visible groups via `activeGroupTab`. Tab counts in the navigation row inline their own filter logic (ternary for "All", explicit filter loop for per-group) rather than calling `getStatusCount`, which creates a maintenance divergence but produces correct numbers.

The rename is minimal and backward-compatible. Import accepts both old (`nexus-full-backup`) and new (`thoughtflow-backup`) type identifiers; localStorage keys are unchanged.

## Duplicated group defaults in full-backup import

The full-backup import path includes a fallback:

```jsx
setTaskGroups(defaultProj.taskGroups || [
  { id: 'tg-today', name: 'Today', order: 0 },
  { id: 'tg-later', name: 'Later', order: 1 },
  { id: 'tg-waiting', name: 'Waiting', order: 2 },
  { id: 'tg-research', name: 'Research', order: 3 },
  { id: 'tg-followup', name: 'Follow-up', order: 4 },
]);
```

These five groups must also exist in the initial state definition elsewhere in `App.jsx`. If one list is updated without the other, a full-backup import of an old file (missing `taskGroups`) would silently produce stale defaults. The fix is trivial: extract `DEFAULT_TASK_GROUPS` as a module-level constant.

## Header count vs. filtered body mismatch

The panel header renders:

```jsx
<span className="text-xs text-slate-400 font-medium">({tasks.length})</span>
```

This is the global unfiltered count. Meanwhile the group tab row and the status filter row both show filtered counts. A user filtering to "WIP" tasks in the "Today" group sees a header saying "(12)" but only 3 tasks below. Replacing with `filteredTasks.length` or removing the header count entirely (since the tab/status bars already display scoped counts) would eliminate the confusion.

## cancelledRef and the Enter-then-blur sequence

The `cancelledRef` approach correctly handles Escape: the ref is set to `true` before blur fires, so `commitEditTitle` is skipped. But on Enter:

```jsx
onKeyDown={(e) => {
  if (e.key === 'Enter') commitEditTitle(task.id);
  if (e.key === 'Escape') { cancelledRef.current = true; setEditingTitleId(null); }
}}
```

`commitEditTitle` sets `editingTitleId` to null and clears `editingTitleValue`. If blur fires after (which it can, since the input loses focus when React removes it from the DOM on re-render), `cancelledRef` is still `false`. The blur handler calls `commitEditTitle` again. At that point `editingTitleValue` is `''`, so the trim-check prevents the update from propagating. No data corruption occurs, but `onUpdateTask` may be called with a no-op update depending on the React batching timing. Setting `cancelledRef.current = true` inside `commitEditTitle` after a successful commit would make this airtight.
