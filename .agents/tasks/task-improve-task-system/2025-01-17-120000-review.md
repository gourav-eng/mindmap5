# Task-card link fix, TaskPanel redesign, and ThoughtFlow rename

Three concerns in one branch: a persistence bug where task-card links and task status indicators went stale after refresh or import, a complete TaskPanel rewrite adding list/card view modes with filtering, and a cosmetic rename from "Nexus Workflow Mind Map" to "ThoughtFlow." The link persistence fix is a solid architectural improvement—moving to `cardTaskLinks` as the single source of truth and removing the redundant `linkedTaskIds` property. The TaskPanel rewrite is substantial (~560 lines replaced) and introduces useful UX patterns. The rename is conservative, preserving localStorage keys and accepting both old and new backup types on import.

**Watch for:** Card View bypasses the group/status filters (confirmed). The "All" tab count in group navigation doesn't respect status filter, creating a count mismatch (confirmed). Inline title editing has a blur/Escape race where blur fires `commitEditTitle` before Escape can cancel (likely).

## High-level view

The persistence fix eliminates a stale-data class of bugs by making `cardTaskLinks` the authoritative source for task-card relationships. The canvas status dot now queries `cardTaskLinks` at render time instead of reading a property (`linkedTaskIds`) that was only written at task-creation time and never updated on delete. Import and export paths now explicitly serialize and restore task state, closing the gap where a single-workspace export would lose all tasks.

The TaskPanel redesign replaces a single card-based view with a dual-mode panel: a dense list view (default) with inline expand/edit, and the original card view as a secondary option. Group navigation tabs and status filter buttons sit above the content area, letting users slice the task list along two dimensions simultaneously. The list view groups tasks under collapsible section headers when viewing "All," and flattens them when a specific group tab is selected. However, Card View ignores both filters entirely, and the tab counts don't reflect the active status filter.

The ThoughtFlow rename touches only user-visible strings and export filenames. localStorage keys are unchanged, so existing users keep their data. The full-backup import accepts both `nexus-full-backup` and `thoughtflow-backup` type identifiers.

<summary>Issues (4)</summary>

1. **Card View ignores filters** — `renderCardView()` uses `getTasksForGroup(group.id)` which doesn't apply `statusFilter` or `activeGroupTab`. Apply `getFilteredTasks()` or filter within the card view renderer.
2. **"All" tab count ignores status filter** — The group navigation "All" tab always shows `tasks.length` regardless of the active status filter. Use `getStatusCount('all')` or similar logic for consistency.
3. **Blur/Escape race in inline title edit** — Blur fires `commitEditTitle` before the Escape keydown can cancel. If the field is empty, the guard prevents damage, but if the user typed something wrong and hits Escape expecting cancel, blur commits first. Add an `isCommitting` ref or prevent blur on Escape.
4. **No input validation on imported task data** — `handleImport` blindly calls `setTasks(importedData.tasks)` without validating structure. Malformed task arrays could crash the panel.

## Single source of truth for card-task links

The canvas status indicator at line ~4488 now performs a live lookup from `cardTaskLinks` instead of reading the stale `node.linkedTaskIds` property:

```jsx
const link = cardTaskLinks.find(l => l.cardId === node.id);
if (!link) return null;
const linkedTask = tasks.find(t => t.id === link.taskId);
```

Old saved data may still carry `linkedTaskIds` on node objects. It's harmlessly ignored now but will never be cleaned up from localStorage—a minor data hygiene point worth a future migration pass if node objects grow.

## Duplicated default task groups

The full backup import hardcodes fallback task groups:

```jsx
setTaskGroups(defaultProj.taskGroups || [
  { id: 'tg-today', name: 'Today', order: 0 },
  ...
]);
```

This list is duplicated from the initial state definition. If the defaults ever change, this fallback will drift. Extract to a shared constant.

## Card View doesn't respect active filters

`renderCardView()` iterates `sortedGroups` and calls `getTasksForGroup(group.id)` which returns `tasks.filter(t => t.groupId === groupId)` with no status or group-tab filtering. A user who selects a status filter and then switches to card view sees all tasks unfiltered—contradicting the filter UI that remains visible above.

The list view correctly applies both filters via `getFilteredTasks()`. The card view should do the same.

## Count mismatch in group navigation tabs

The "All" tab displays `tasks.length`—the unfiltered total. When a status filter is active, the visible task count is lower. Per-group tab counts (`getTasksForGroup(group.id).length`) similarly ignore the status filter. `getStatusCount` correctly scopes to the active group tab, but the group tabs don't scope to the active status—the filtering is asymmetric.

## Blur/Escape race in inline title editing

The Escape handler calls `setEditingTitleId(null)` to cancel. But the input's `onBlur` fires `commitEditTitle` which writes `editingTitleValue` back. In browsers, blur fires before keydown in some scenarios (e.g., focus moves on Escape in certain environments). If `editingTitleValue` is non-empty and different from the original, the unwanted value gets committed before Escape can cancel. A common fix is to set a flag in the Escape handler and check it in the blur handler.
